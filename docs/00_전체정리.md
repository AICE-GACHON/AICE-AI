# 📌 card-rag 전체 정리 (여기부터 읽으세요)

> 헷갈릴 때 돌아오는 지도. AI(추천) 파트가 지금까지 무엇을, 왜 만들었는지 쉬운 말로 정리.
> **최종 갱신: 전체 인제스천 파이프라인 실제 가동 + 자연어 Q&A 완료 시점.**

---

## 1. 우리가 만드는 것 (한 줄)

**내 위치 주변 가게에서, 내가 가진 카드 중 지금 결제하면 가장 이득인 카드를 "얼마 이득" + "왜"까지 알려주는 앱.**

핵심 철학:
> **숫자 계산은 '규칙 엔진'이 정확하게, 애매한 약관 판정과 설명만 'AI(RAG)'가.**
> AI는 규칙 엔진이 계산한 숫자를 절대 못 바꾼다(= 가드레일).

왜? 카드 혜택은 "적립률·한도·전월실적" 같은 **숫자**와 "스타벅스는 되고 개인카페는 안 됨" 같은 **애매한 말**이 섞여 있다. 숫자를 AI에 맡기면 환각(거짓 숫자)이 나니, 숫자는 규칙으로 고정하고 애매한 말만 AI가 판단한다.

---

## 2. 큰 그림 — 두 개의 파이프라인

### 🅰 인제스천 (카드 혜택을 DB에 넣기) — **전체 작동 ✅**
```
카드 약관 원문 → 정규화 → LLM 추출 → 자동 검증 → 임베딩 → pgvector 적재 → 벡터검색
   (수집)        (텍스트)   (Haiku)   (스키마·정합)  (Cohere)   (Postgres)     (유사도)
     ✅            ✅         ✅          ✅           ✅          ✅            ✅
```

### 🅱 추천 (사용자가 추천 요청 시)
```
규칙 엔진        →  triage         →  retrieve/grade   →  LLM 판정      →  가드레일
(구간별 최적카드)   (LLM 필요한지)     (가맹점↔조건 매칭)   (자격/설명)      (숫자 불변)
   ✅               ✅                ✅               ✅              ✅
```
> **LangGraph로 배선 완료.** `card-rag recommend "스타벅스 강남점"` → 구간별 최적 카드 + 근거 + 제외사유.
> RAG가 실제로 추천을 바꿈: '블루보틀'에선 화이트리스트 미포함 카드가 자격 미달로 빠짐.

### ➕ 자연어 Q&A (별도 기능) — **작동 ✅**
자유 질문 → 관련 혜택절 검색 → Haiku가 근거 인용해 답변. (예: "배달앱으로 스벅 시키면 K-패스 혜택 돼?" → "아니요, 배달앱 제외")

## 3. 진행 로그 (라운드별)

| **1. 계획** | 노션 정독, 담당 범위·레포·데이터 방식 결정 | 방향 확정 |
| **2. 데이터 방식** | 약관 구조화 방법 | LLM 추출, 포함/제외 분리 임베딩 |

| **5-3. 환경·가동** | 64비트 Python 전환 | **인제스천 파이프라인 실제 가동** |

## 4. 꼭 알아야 할 핵심 개념 3개

### ① 하이브리드 (규칙 + RAG)
숫자는 규칙, 애매한 말은 AI.

### ② triage = "이 후보에 AI를 쓸까 말까" 판단
AI 호출은 비싸다. **(조건이 애매함) 그리고 (그게 순위를 바꿀 수 있음)** 일 때만 부른다.
예: A카드가 애매한 조건 뒤집혀도 여전히 1등이면 → AI 안 부름(답 안 바뀜).

### ③ 규칙 엔진 = "결제액에 따라 유리한 카드가 달라짐"
결제액을 하나로 가정하지 않고 **"몇 원 이상이면 어느 카드"** 구간을 계산.
```
1만원 미만  → 토스뱅크 (정액 100원)
1만원~5만원 → 토스뱅크 (정액 500원)
5만원 이상  → K-패스 하나 (1%)
```

```
│   ├─ ingestion/

│   │   └─ validate.py          ← 자동 검증(사람 검수 대체)

│   │   ├─ judge.py             ← LLM 자격 판정 + 가드레일 ✅

│   └─ cli.py                   ← 명령어
├─ tests/                       ← 순수 로직 테스트 12개 (전부 통과)
└─ docker-compose.yml           ← pgvector Postgres (cardrag-db 실행 중)
```

## 6. 우리가 내린 주요 결정들

| 주제 | 결정 |
|---|---|
| 담당 범위 | 추천 도메인 **전체**(규칙 엔진 + RAG) |
| 레포 | `card-poke`에 독립 프로토타입, 나중에 BE로 이식 |
| 데이터 | 약관 → LLM 추출 → **자동 검증** → 적재 (전체 자동화) |
| 임베딩 | 포함/제외 조건을 **각각 따로** 임베딩 |
| AI 트리거 | (조건 애매) **그리고** (순위 좌우)일 때만 LLM |
| 근거 불충분 시 | **관대** — 제외에 명확히 안 걸리면 적용 |
| 결제금액 | 고정 안 함 → **"N원 이상이면 X카드" 구간 추천** |
| 정액/정률 | `value_type`(percent/flat) 필드로 둘 다 지원 |
| 한도 | 남은 월 한도(`remaining_cap`) 반영 |
| RAG 확대 | **A(약관 심화 판정) + B(자연어 Q&A)** |

## 9. 실제로 돌리는 명령어 (지금 작동)
```bash
# 파이썬은 venv 것을 쓴다 (64비트)
.venv\Scripts\python.exe -m card_rag.cli init-db          # DB 초기화(1회)
.venv\Scripts\python.exe -m card_rag.cli ingest <카드id>   # 새 카드: 수집파일→자동 완주
.venv\Scripts\python.exe -m card_rag.cli load <카드id>     # 검증된 카드 적재
.venv\Scripts\python.exe -m card_rag.cli ask "편의점 만원, 어떤 카드?"   # 자연어 Q&A
.venv\Scripts\python.exe -m card_rag.cli recommend "스타벅스 강남점"      # 추천 end-to-end
```
> 새 카드 추가: `data/raw/<카드id>/benefits.md`에 원문 넣고 `data/cards.json`에 메타 추가 → `ingest`.

순수 로직 테스트(설치 불필요, 아무 파이썬):
```bash
python tests/test_rule_engine.py && python tests/test_triage.py && python tests/test_retrieval.py
```
